## Summary

**Verdict: no regression found, but the build is NOT proven final.** Every control plane Deployment and the landing page run the registry digest of `pr-33` and no old ReplicaSet pod is left. The agent sidecar of every session pod does not: all 6 session pods that exist or were created during the run carry agent digest `sha256:b6fc6a97...`, the registry says `sha256:1b16df61...`, and the agent logs the version `pr-33-e5ccd2f4bd09` (the mixed build of the first run, PR head `4066ed1`) instead of `c2b2043`. Cause: the operator sets no pull policy on the agent container (Kubernetes default `IfNotPresent` for a non-`latest` tag), the tag `pr-33` is mutable, the nodes cache the old image ("already present on machine"), and the pool's spec hash only covers the tag string. So the idle pool instances were also NOT replaced by the deploy (finding 1 and 2). The IDE images are final (digests equal the registry, plugin versions as expected). Everything the agent does was therefore tested against the old agent build, not the final one.

With the feature off, everything checkable without a login behaves as in the first run: warm and cold start, launch data handling and the operator's second allowlist, agent control and proxy listeners, session pod isolation and egress, workspace retention, RBAC (Roles equal what the chart renders), the eight NetworkPolicies (equal to the render and to revision 3), public status without `gitProviders`, no `git-proxy` or git-account objects, no internal port on the service's Service, no `AGENT_GIT_*` env and no `insteadOf` entry. Logs since 11:31 UTC have no ERROR and no panic; the only WARN lines come from my own fixtures. No 429 and no rate-limit message. One real-user launch got a 400 because its `GIT_URI` host is not in `allowedHosts` (expected, finding 4).
