# Functional check test2.eduide.student.k8s.aet.cit.tum.de, 2026-11-17 (run 1)

First full run of the functional test plan. No tokens, cookies, Secret values, session env values or personal data in this file. The logged-in browser account is called "the test account".

## Executive summary

- test2 on chart 3.0.0-rc.3 with EduIDE-Cloud 3.0.1 is fit for further rc testing: 86 of 104 planned tests pass, 3 fail, 6 are blocked, 9 skipped (5 of them Artemis). No critical finding.
- Every check from the 2026-11-16 security audit still holds, and every IDE template on `pr-233` (scorpio 3.1.0) builds, runs and tests cleanly.
- Restarts, a rollback to Cloud 3.0.0 and the redeploy kept sessions, claims, URLs and files intact. The end state equals the deploy workflow's state.
- Most important defects (all EduIDE-Cloud): after an operator restart, sessions with a closed tab are never ended by inactivity (F2); a replaced session pod loses its injected data (F3). Every deploy restarts the operator (F19), so both hit on every deploy.
- Warm pool: pool reconciles delete the sidecars of pool instances (F1, latent, no catalog app uses this today); broken free instances are still handed out (F4); orphaned claims are repaired only by chance (F5).
- Security hardening: session pods reach node SSH, kubelet and the API server on the public node subnet (F6, all deny anonymous access); a VCS token sits in clear text in one Session CR's `GIT_URI` (F7).
- Alerting is switched off on the cluster, so three monitoring tests are blocked; once switched on, two certificate alerts would fire for other tenants' certificates (F12, F13).
- The plan was updated in the same PR: 19 new tests, corrected expectations and helpers (see the last section).

## Exploration highlights

The part files hold the full list (about 60 explorations). What found nothing is as useful as what found something:

- Nothing served IDE content anonymously across 30 path-normalisation variants; no value echo in bridge error messages; no token in service or operator logs; foreign workspace names are refused (403).
- Concurrency held: three claims in one second gave exactly one eager and two lazy sessions; ten tight claim/delete cycles left no stuck claim.
- Interruptions held: graceful service pod deletion during a launch, operator scale to 0 with changes while down, rollback and redeploy with running sessions.
- Not tried (time or shared-cluster limits): 20 sessions at once, disk full, 100k lines of output, two tabs on one session, a second Keycloak account opening another user's URL.
