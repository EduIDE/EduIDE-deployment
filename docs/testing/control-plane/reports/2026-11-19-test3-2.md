## Summary

- All open failures of run 1 that belong to this repository are fixed and re-tested: OPR-07, 08, 11, 12, POOL-06, 08, 13, SEC-11, MON-01 to 04, MON-06 (labels), MON-11 and IDE-05 pass.
- Every browser half that run 1 left blocked now has a result: AGENT-12, 14, 15, 16, OPR-04, LAND-09, WS-11, AUTHZ-05, 08, 10, SEC-15, IDE-07 and IDE-10 (details below).
- The launch trace now covers the whole path from the click to a usable IDE: `launch` in the service, `start` with `claim`, pod phases and `agent.claim` in the operator, and the late spans `browser.connect`, `ws.connect`, `ide.load`, `data.delivered`, `workspace.ready` and `ide.usable` from agent and extension milestones, all in one trace.
- Two real defects were found and fixed during the run: socket.io long-polling broke after 15 s (gateway request timeout, `b9b6dd1`) and temporary sessions showed "Saved workspace" (an `emptyDir` was mounted, `1ff2d66`).
- Two new high findings in the session login path:
  - R2-6 is fixed in EduIDE/EduIDE-control-plane#2 and re-tested on test3: the retries of an IDE locked the browser out of the instance host for 10 minutes.
  - **R2-5 is open and blocks production**: once the gateway client's token expires (Keycloak default 5 minutes), an open IDE gets 401 for every new HTTP request and WebSocket reconnect until the student reloads. This includes lazily loaded IDE parts such as the editor worker and plugin assets. It needs a decision (see the finding).
- One new low finding for the landing page (R2-1): after a service outage the template tiles stay empty until a reload.
- Still open and not in this repository: MON-07 (Grafana only reads `cattle-dashboards`, a cluster decision), MON-08 (cluster certificate alerts), PLAT-11 (webview listener overlaps the shared Gateway). Still open and needing the owner: LAND-01, LAND-10, LAND-11 (logout and a fresh login).

| R2-5 | high, open, blocks production | Once the gateway client's token expires (Keycloak default 5 minutes after the last login), an open IDE gets 401 (before #2: a CORS-blocked redirect) for every new HTTP request and every WebSocket reconnect until the student reloads the page. Lazily loaded IDE parts fail too: on test3 `editor.worker.js` and the plugin assets under `hostedPlugin/` of a Java IDE that took longer than 5 minutes to load. A page reload logs in again silently. Cause: Envoy sets the Max-Age of the ID token cookie to the token lifetime, the browser drops the cookie, and because ext_authz runs before the OIDC filter, the refresh with `refreshToken: true` never happens. `disableTokenEncryption` leaves the refresh token encrypted, so authz cannot read it either. No code; logging out of Keycloak no longer ends IDE access before that time. (b) authz issues its own HttpOnly session cookie (owner, HMAC, bound to the encrypted refresh token cookie) and accepts it while the OIDC filter refreshes. Code, review and ADR, revocation within 5 minutes. Recommendation: (a) now for test3 and the first production run, (b) as a follow-up. |
